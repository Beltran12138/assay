## 1. cardio-02 · 减脂要不要做有氧运动

````text
你觉得非洲部落的人每天徒步 20~30 公里狩猎采集，活动量远超现代任何健身爱好者。那他们的总能量消耗和现代久坐办公室人群哪一类更多？
你的第一反应是不是觉得肯定是非洲部落的人消耗的热量多？
但科学研究表明，他们的总能量消耗，几乎一样。部落的人的确会多出一点，但多的有限。
其实这是因为人体有一个总能量预算。
当你增加运动消耗时，身体不会像计算器一样，多动它就多消耗直接往上累加，而是会悄悄地从其他地方省回来，比如降低基础代谢，减少非运动活动，让人更嗜睡，甚至降低免疫和生殖系统的能耗。
这就是受限总能量消耗模型。
换句话说，假如你跑步消耗了 300 大卡，身体可能偷偷又从别的地方省回了 200 大卡。所以你以为你创造了 300 大卡的热量缺口，实际上只有 100 大卡。
所以纯靠堆有氧运动量，减脂效率必然递减。
而且如果你的减脂方案是纯做有氧运动加节食，那么你掉的不只有脂肪，还有肌肉。
肌肉是我们身体消耗热量的大户，每公斤肌肉每天在安静状态下也要消耗约 13 大卡。听起来不多，但如果你掉了 3kg 肌肉，每天就会少消耗约 40 大卡，一年就是 14600 大卡，约 4 斤纯脂肪。
而且肌肉量还会直接决定你的基础代谢率。
越少吃、多跑，身体就越觉得饥荒来了，它的第一反应绝对不是消耗囤积的脂肪，而是先把最耗能的大户肌肉给拆掉，把脂肪死死的囤起来，关键时刻才用。
就这样少吃、多动，导致身体偷偷降代谢。你为了度过这个平台期，如果继续吃得更少、动得更多，只会让代谢降得更低，进入恶性循环。
所以我们现在知道了身体在干什么，那我们接下来的解决办法就好说了。
核心思路不是多运动多消耗，而是让身体无法适应，无法节能，同时保护你的肌肉。
首先， 力量训练优先， 有氧靠后
把力量训练放在每次训练的主位，有氧作为补充。
因为你在做力量训练的时候，是在给身体一个信号，告诉它我现在还需要用到这些肌肉，所以你不能把它拆掉。
在有热量缺口的前提下，这个信号非常重要，意味着它告诉身体能拆脂肪，但拆肌肉不行。
你可以每周做 3 次力量训练， 每次 40~50 分钟。
以复合动作为主，比如深蹲、硬拉、卧推、划船、推举。
每次力量训练选 4~5 个动作，每个做 3~4 组，每组是 8~12 次。
有氧运动可以放在力量训练之后，或者单独安排，每次可以做 20~30 分钟。
假如说你时间有限，那么宁可砍掉有氧运动，也不要砍掉力量训练。
但是有一点要注意，一定要关注力量训练的量，它不是越多越好。
````

## 2. cardio-04 · 减脂要不要做有氧运动

````text
不需要。 减肥的底层逻辑是制造热量赤字（每日摄入热量小于总消耗热量），而有氧运动只是增加热量消耗的手段之一，并非必要条件。
不靠有氧减脂的 3 个核心途径
控制饮食： 减脂期约 70%–80% 的热量缺口来自饮食控制。只要将每日摄入控制在合理区间（低于每日总能量消耗 ），即使不运动也能实现减重。
力量训练： 力量训练在消耗热量的同时能刺激肌肉生长、防止肌肉流失。更高的肌肉量有助于维持更高的基础代谢率，使身材更紧致，避免减重后出现皮肉松弛。
提高日常非运动消耗： 包括走路、站立、做家务、爬楼梯等。每天多走几千步所积累的热量消耗，往往不亚于半小时慢跑。
高效减肥策略推荐
最佳组合： 饮食控制（制造热量缺口） + 力量训练（保住肌肉） + 保持高日常活动量（如每天不低于 8000 步）。
````

## 3. cardio-10 · 减脂要不要做有氧运动

````text
碳水：糙米、山药、芋头、地瓜、土豆等等
脂肪：肉类中的脂肪、橄榄油
第三个月的时候我的晚餐热量会减得更少，一周大概5天都自己做沙拉，2天和之前一样。
两周大概会出去随便吃一次，这里指的的去social去饭店去下馆子，而不是暴饮暴食。
因为如果饮食过分的严格，心态很容易崩，也无法坚持控制饮食三个月。
除了这每两周一次“放纵”，平日里的饮食会很固定。
因为如果变化太大，卡路里不好计算和确保。
扣除完了三餐，接着再扣除蛋白粉（2勺）的热量，大约242卡(1582kJ/4.186*0.32*2)。
这样，还有大约还有158卡的“额度”。
这些额度分配给一些零食，如果能够控制住不吃，那么就可以制造更大的热量差。
接着说锻炼方面。
锻炼方面和之前增肌时候没什么变化，该怎么练还是怎么练。
只是在减脂的时候没有去尝试更大的重量。
减脂时期力量训练是必不可少的。
一个是为了增加更多消耗，消耗身体中的糖原，避免糖分储存起来；
另一个是为了尽可能避免减脂期肌肉的流失。
有些人认为减脂期只需要做力量训练，无需做有氧。
这么说也对，如果有一定的肌肉量，确实只需要做力量训练，积累一定的运动量后自然就会瘦了。（所以常会看到网上一些健身教练或者肌肉量大的人支持减脂只做力量训练的说法，这么说也没错）
但是，对于本身肌肉量就不是很大的人群来说，只做力量训练对于减脂来说效果就不好了，这样的人群同时还需要配合有氧运动。
我自认为我的肌肉量并没有那么大，所以我一周4练，除了练腿的那天不做有氧，其他3天在大约1小时候力量训练后，会增加30分钟左右的有氧运动。
有氧运动并不是单纯在跑步机、椭圆机、登山机上随便动一动就属于有氧，也是有讲究的。
根据目的的不同，有氧运动又分为热身、锻炼心肺能力、减脂等等。
有氧运动的关键就是在于对心率的要求，目的不同，对运动时候心率的要求也不同。
简单说，有氧运动之所以是叫有氧运动是因为运动过程中是身体的供能系统是有氧代谢的方式进行的。
有氧代谢的过程是脂肪和氧气经过一系列化学反应的过程。
因此，运动时候强度不能过大，导致氧气无法参与有氧供能，从而降低消耗脂肪。
而如果运动强度太低了，又会导致效果过小，减脂的效率也会下降。
由于这么说很抽象。
所以，人们用运动时候的心率来量化这个过程。
有氧运动遵循的原则是，你要在运动时让足够的氧气参与你身体的代谢，同时又要保证运动的强度。
而做到这点，需要通过控制心率（Heart Rate, HR）来达成，你要将你在运动时候的目标心率（Target Heart Rate）控制在75%-85% MHR。
````

## 7. python-vs-c-04 · 编程新手先学 Python 还是 C

````text
首先给你吃颗定心丸：绝对能学好！ 事实上，Python 是目前公认对零基础最友好的编程语言。但“能学好”不代表“没有困难”，关键在于你如何跨越新手期的阵痛。
为了让你少走弯路，我们可以从以下几个维度来客观分析：
一、 零基础自学 Python，难点到底在哪里？
思维转换的阵痛（最大难关）
编程不是背单词，而是学一种“逻辑表达”。初学者最容易卡在“循环”、“条件判断”、“函数”等抽象概念上。有时候代码明明是对的，但就是跑不通，这种挫败感很容易让人放弃。
环境配置与报错处理
刚开始学，很多人连 Python 环境都装不好，或者遇到满屏的英文报错（Error）就发懵。其实报错是程序员最好的朋友，但新手往往缺乏“看懂报错并独立搜索解决”的能力。
“教程地狱”（Tutorial Hell）
这是自学最大的陷阱：跟着视频敲代码觉得全懂了，一关掉视频自己写就大脑空白。这是因为你只停留在“看懂”的表层，没有真正转化为自己的肌肉记忆。
二、 为什么说 Python 是最适合新手的？
尽管有上述困难，但 Python 的优势足以帮你克服它们：
语法极简： 它非常接近人类自然语言（英语）。比如打印一句话，其他语言可能需要三行代码，Python 只需要 print("Hello")。
正反馈快： 你不需要懂底层的内存管理，就能快速写出爬虫抓取网页、自动化处理 Excel 表格，或者做个人网页。
这种“成就感”是支撑你学下去的最佳燃料。
````

## 10. python-vs-c-13 · 编程新手先学 Python 还是 C

````text
最近不少人邀请提问我：”零基础，学什么语言好？”
我理解你为什么要问，但换个角度想，就好比你走去问厨师”我应该学做什么菜”，但又不告诉人家你开的是大排档，还是早餐店，那人家怎么回？
所以想统一讲下这件事。不讲哪个语言”无敌”，也不列什么对比表格。就讲一件事：先搞清楚你为什么要学，然后路就自然出来了。
先问自己一句：你是为了什么而学？
一开始没想清楚目的，学着学着就走偏了，身边应该不少这样的人。所以与其直接给你推荐语言，不如先把这件事讲明白。讲到底，学编程这件事，多数就三种理由：图个兴趣、为了就业、想转行。理由不同，该走的路也都完全不一样。
图个兴趣的人
要是你只是想了解一下编程是什么一回事，我建议先从 C 入手。
C 语言能帮你先搞清最底层的原理，比较：变量、指针、内存，这些东西后面学什么语言都用得上。而且 C 有个隐藏的好处：它有点劝退。呵呵，无错，听着像坏话，其实是为你好。真不适合吃这碗饭的人，学着学着自己心里就有数了，省得硬撑浪费时间。
但万一你越学越上瘾，劝都劝不住呢？那就看你心里面最想用编程来做什么事。想做游戏，Unity 引擎背后站的是 C#，Unreal 那套对应 C++（不过新手先劝退 C++，后头会讲）。想做网页上的小游戏或者前端交互，TypeScript 更规范合适些。总之，尽量让项目带你去选语言，哪个能让你做出东西来，就用哪个。
至于那些暂时还不知道自己想做什么，就是纯觉得编程这件事有意思，那就学 C# 或 Java，先上车再讲。这两门后面真要找工作也用得上，不亏。
为了就业去的人
这里要先分清楚一件事：你是软件相关本专业，还是非软件专业？
软件本专业的同学，其实无什么好纠结的，跟着学校的课程一步步走就是了。学校一般拿 C 打基础，再教些现在就业市场常用的或者新兴的语言。这条路走通了几十年，照着走就行，下限有保障，不至于差得去哪。
非软件专业的朋友，情况就有点复杂了。这里又分两种情况：
・将来还是想从事本专业工作，那不一定非得补一门”正统”的基础语言，最好是学个能帮你本职工作提效的。比如你做财务，天天跟 Excel 打交道，学点 VBA 或 Python，效率能翻倍。这种情况下，脚本语言反而更适合。
・希望彻底转去做软件开发，那就建议直接学 C# 或 Java，别碰脚本语言。原因我后面会一齐讲清楚，这里先记住这个结论就好。
想转行的人
转行的朋友，通常都是想直接转去开发。
不管你之前有无基础，我都建议直接学 C# 或 Java。
````
